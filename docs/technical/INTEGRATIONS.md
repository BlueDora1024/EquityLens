# 外部集成与数据契约

## Longbridge

正式实现使用 Longbridge Python SDK 4.4.3。OAuth 由 `OAuthBuilder` 发起浏览器
授权，授权后由 `Config.from_oauth()` 创建配置；SDK 自动持久化和刷新 token。
应用通过长桥动态客户端注册取得 Client ID，普通用户无需创建或填写。完整首次授权、
质检与恢复规则见[首次配置与设置](FIRST_RUN_AND_SETTINGS.md)。

平台只依赖以下能力：

| 能力 | 必需字段 |
| --- | --- |
| 证券资料 | symbol、名称、市场、描述、资产类型提示 |
| 交易日 | 市场、日期、是否完整收盘 |
| 服务端量化 | symbol、interval、起止时间、脚本、命名数值序列 |
| 日线（RS 基准例外） | symbol、交易日、close |
| 原始多周期 K 线（测试替身/兼容） | symbol、interval、timestamp、OHLC、volume |
| 快照 | symbol、last price、market value（可空） |

所有时间戳进入领域前必须带时区并升序去重；命名序列必须与时间轴对齐。批量资料
最多 100 个 symbol；量化执行按证券、周期拆分并最多 2 路并发，在每次请求前检查
取消。Longbridge Quant 使用直连 HTTP，不依赖 QuoteContext 的 SDK 限频器；生产
组合根把请求启动间隔固定为 750ms（约 1.33 次/秒），为该直连接口的滚动限频桶、
交易日、快照和同账户其他客户端保留余量，同时保留最多 2 路在途请求隐藏单次网络
延迟。首个请求单路完成授权/权限探测，成功后才放开并发；HTTP 429、业务码
`301606` / `429002`，以及“request is limited”响应均进入同一限频恢复路径。
服务端没有 `Retry-After` 时等待 10 秒并把本次运行保持为一路。完整交易日、复权
方式和边界包含行为由适配器统一处理。Longbridge Quant
把结束日期视为排他上界，因此适配器查询时推进一个自然日，解析后再严格裁剪至
调用方请求的结束时间；领域层始终得到包含截止日且不包含下一日的数据。

日期边界由共享 `DateProbeWindow` 处理。首尾分别向外扩展四个工作日，只扩大
取数包络，不改变用户请求区间或算法范围；解析后向区间内部选择实际边界。领域、
历史和导出分别保存 requested、fetch 与 actual 日期，避免把周末或休市回退伪装
成用户原始选择。

量化结果只保存已完成区间，以 Provider、证券、周期、精确起止和脚本版本为缓存键。
一次运行使用批量键查询和单事务批量写入。拐点与极值偏离共用规范化 OHLC 缓存；
缓存除了行数还保存“已覆盖到哪个目标完整 K 线”的水位，水位落后时只补带少量
重叠的尾部数据，禁止把旧数据误判为命中。领域层使用完整可用历史预热本地公式，结果 payload 只冻结
最近 100 根图表证据。Longbridge 当前不保证
`request.security` 跨证券脚本可用，因此不伪造批量能力；若未来官方稳定支持，
只替换 Provider 适配器，不改三个工具的算法。

Provider 返回逐 symbol 成功或稳定错误，不把部分失败升级成整批异常。Quant
自动恢复矩阵固定如下；重试设为 0 会完全关闭自动恢复，启用后按表中的安全上限执行：

| 稳定错误 | 自动重试 | 批次动作 |
| --- | --- | --- |
| `timeout` / `network_error` | 最多 2 次，等待 1s、2s | 仍失败则跳过；达到熔断阈值停止新请求 |
| `service_unavailable` / 5xx / `internal error` | 最多 2 次，等待 1s、2s | 仍失败则跳过；达到熔断阈值停止新请求 |
| `rate_limited` / 429 / `301606` / `429002` | 遵守 `Retry-After`，缺失时等待 10s；最多 2 次 | 暂停补充任务并将本次运行保持为一路；重试耗尽只跳过当前证券，持续错误达到统一熔断阈值才停止全批 |
| `malformed_response` | 最多 2 次，等待 1s、2s | 仍失败只跳过当前项 |
| `authentication_failed` / `permission_denied` | 0 次 | 立即停止相关行情任务 |
| `quota_exhausted` | 0 次 | 立即熔断 |
| `data_unavailable` / `insufficient_data` | 0 次 | 跳过当前项 |

RS 日线量化在完成上述有限重试后，若仅个别证券仍得到
`malformed_response`，会只为失败证券补一次同源 Longbridge 原生日线请求。补取成功
则继续计算，失败则使用原生日线的稳定错误原因跳过；`data_unavailable`、权限、额度
等确定性错误不追加请求。该恢复不改 Provider、不重跑已成功证券，也不触发 Yahoo
整轮备用。

基础设施错误连续 8 次，或最近 20 个已完成任务中同类错误达到 16 次，也会打开
运行内熔断器。等待和补充任务前都会检查取消；UI 线程不参与 sleep。Quant 失败
禁止静默改成大量 Longbridge 原始 K 线请求；除上述“单只失败、单次同源”的有界
恢复外，只有下述用户批准的 Yahoo 备用路径
可以显式从第一步重跑整次冻结请求。SPY/QQQ 的 RS 基准日线仍是主路径内唯一
明确例外。

运行前资源预检只读取股票池与 SQLite，不调用 Longbridge。资源卡按冻结请求显示
理论任务、精确缓存命中、预计物理外部请求和实际路径；物理请求超过 50 时必须由用户
确认，确认前后请求参数完全一致。

长桥不能可靠提供真实业务板块，也不能始终区分普通股、ADR、ETF、REIT 等，因此
公司描述与资产提示会交给 AI 做兜底，最终仍由本地白名单校验。

## Futu OpenD

富途实现固定使用 `futu-api==10.9.6908`，只创建
`OpenQuoteContext(host="127.0.0.1", port=11111)`。Futu OpenD GUI 负责账号登录
和官方协议；本软件不保存富途账号、密码或 token，不创建交易 context，不接入交易、
资产、持仓、订单、解锁或下单能力。

| 能力 | OpenAPI |
| --- | --- |
| 证券资料 | `get_stock_basicinfo`、`get_owner_plate` |
| 快照 | `get_market_snapshot`，每批最多 400 |
| 交易日 | `request_trading_days` |
| 历史额度 | `get_history_kl_quota(get_detail=True)` |
| 日线与多周期 K 线 | `request_history_kline` |

规范代码 `AAPL.US` 在边界映射为 `US.AAPL`。所有历史请求固定
`autype=NONE`、`session=RTH`、`extended_time=False`，单次最多 1000 根；拐点的
30m、60m、120m、240m、日线和周线分别映射官方周期，极值偏离仅使用 30m、60m、
日线和周线。拐点 220 根与极值偏离 650 根窗口通常各用一次请求完成，只有真实响应
超过 1000 根才继续分页。官方 30 秒
60 次限制只约束首次历史请求，适配器严格串行并保证首请求至少间隔 0.5 秒（约
2 次/秒）；续页不重复等待，
但仍逐页检查取消，并只对瞬时网络/超时做有限重试。

历史额度按滚动最近 7 天请求过的不同证券计数。三个工具运行前先读取额度明细，
把股票池与基准去重后区分“可复用证券”和“新证券”；不足时在任何 K 线请求前
阻断并展示缺口。资源预检本身只读取一次额度和本地缓存，不请求 K 线；多选周期或
RS 多选范围不会把同一证券重复计入滚动额度。正式运行仍由 Provider 在发出历史
请求前执行最终保护校验，避免预检后额度被其他客户端消耗。预计物理请求超过 50
时，弹窗展示请求数和最快耗时，用户可继续富途或在发起首个富途行情请求前改用
Yahoo 整次重跑。

Futu 额度缺口大于零时，主供应商操作不可继续。用户选择 Yahoo 后只为本次冻结请求
建立 Yahoo 运行，从第一阶段重新开始；全局当前供应商仍是 Futu。主供应商已经产生
的内存临时结果会被丢弃，完成历史不得混合 Provider。`quota_exhausted` 始终保留为
额度错误；只有行情确实存在但长度达不到算法要求时才报告 `insufficient_data`。

## 物理请求与缓存口径

- Longbridge 原始 K 线每页 200 根：220 根按 2 次、650 根按 4 次计入预算；不得把
  一次领域调用伪装成一次外部请求。
- Futu 每页最多 1000 根，预算另计一次额度检查和命中证券的快照批次；历史首请求
  严格串行。
- Yahoo 按下载批次计数；1h/2h/4h 是一个小时族，只下载一次 1h 后本地聚合。
- Futu/Yahoo 的 RS 完整日线包络按 Provider、证券和精确日期持久缓存；相同结束日
  重跑不再访问上游。所有缓存按 Provider 隔离，接受 Yahoo 备用时整轮只有一个来源。
- 连续 8 次同类基础设施错误或最近 20 项中同类错误达到 16 次即停止提交新请求，
  剩余任务标记为未执行，由一个汇总恢复入口处理，不制造错误弹窗风暴。

富途指标计算要求调用方先提交 K 线，且不能托管本项目的冻结算法，因此不会作为
600 股批量主链路。三个工具使用 OpenD 必要原始行情和同一套本地确定性算法；
缓存键包含 `provider_id=futu`，不会与长桥结果混用。

## 自定义供应商开发

设置页“接入供应商”提供的开发提示词面向已经打开本项目完整源码的 AI 编码助手。
使用前补充供应商名称、官方开发文档、认证方式与只读权限、官方 SDK；执行 AI
必须先检查当前协议、Longbridge/Futu 参考实现、设置存储、组合根和测试门禁，
输出能力矩阵以及 600 只股票运行三个工具的请求预算，再按 TDD 接入。

提示词冻结以下边界：

- 只接入证券资料、交易日历、报价、快照、K 线和技术指标等只读能力，不申请
  账户、资产、持仓、订单或交易权限；
- 复用现有领域 DTO、日期策略、缓存、资源预算、失败分类和 Yahoo 整次重跑，
  不复制分析算法或建立第二套行情模型；
- 只有官方能力确实能完整表达现有命名序列且资源成本更低时才声明服务端量化，
  否则保留原始 K 线兼容路径；
- 新实现先作为候选供应商，完整质检后由用户显式原子切换；失败保留当前供应商
  和全部业务数据。

“重新扫描”只重新读取当前构建中受控注册表的 `ProviderDescriptor`。应用不会
动态导入任意本机脚本；源码实现、测试和代码审查完成后，必须重新构建应用，新
供应商才会出现在设置页。最终验收需要 Mock 契约、真实只读 smoke、全量门禁、
packaged acceptance，并将验证后的应用同步到 `/Applications/EquityLens.app`。

## Yahoo 备用行情

Yahoo 通过固定版本 `yfinance==1.2.1` 随应用打包，不显示为可配置的基础资料
供应商，也不需要凭据。它只实现分析用日线和 K 线，复用设置中的网络代理：

| 工具路径 | Yahoo 输入 |
| --- | --- |
| RS | 复权日线 OHLC；算法只读取 close |
| 拐点 | 30m、1h、日线、周线；2h/4h 由同一次 1h 下载本地聚合 |
| 极值偏离 | 30m、1h、日线、周线，随后由冻结 Python 指标实现本地计算 |

每次运行共享一个 `FallbackSession`。只有 `timeout`、`network_error`、
`service_unavailable`、`rate_limited` 或 `quota_exhausted` 的最终失败可以提出
一次授权；认证、权限、输入错误、确定无数据和样本不足不得触发。用户同意后丢弃
主供应商本次尚未保存的临时结果，用 Yahoo 从第一步重跑完整且不可变的请求；拒绝
或再次失败不会二次询问。整次运行只允许一个行情来源，历史、导出和 AI 证据不再
产生 `mixed` 数据。

Yahoo 下载使用复权价格、关闭自身重试、最多四线程并受应用取消控制。30 分钟
使用上游原生 `60d` 范围，最多覆盖最近 60 天；1 小时使用 `2y` 范围，2h/4h
由同一份 1h 序列本地聚合；日线和周线按目标根数请求足够的日历跨度。当前日期的
真实 NVDA smoke 已验证四个极值偏离周期均能返回至少 650 根。超过保留边界时直接
返回稳定限制原因，不用较短窗口伪造完整结果。备用弹层在请求前明确说明它可能较慢
且某些网络环境需要代理。Yahoo 数据的可用性、授权和个人使用边界受其上游条款
约束，本软件不承诺适合公开再分发或商业行情服务。

Yahoo 不是全产品的无条件替代品：RS 的日线、拐点当前/近期周期、极值偏离当前
30m/1h/日/周可覆盖；超过 60 天的 30m 历史复盘、退市或改名证券、Yahoo 全站
不可用时不能覆盖。全局证券导入和资料更新需要稳定的证券类型、公司描述、市值等
字段，继续只使用正式供应商。`query1`、`query2`、`yfinance` 和 `yahooquery`
都是同一 Yahoo Chart 数据源的不同入口或包装，只能增加传输兼容性，不能作为独立
行情来源，也不能突破 Yahoo 的历史保留限制。当前没有发现无需凭据、同时可靠覆盖
美股公司资料、批量日线和长周期分钟线的公开接口；因此产品选择诚实失败并引导网络
设置，而不是静默拼接来源。未来可增加 Stooq 等日线级独立备用，但它不能解决分钟线
与公司资料缺口。

每个行情 dataset 都带 `source_by_symbol`。正常运行全部记录主供应商；备用重跑
全部记录 Yahoo。逐证券来源、请求/探测/实际日期随历史和完整导出冻结。备用源
不写入证券资料，不改变全局证券、标签或股票池。高级设置“网络与备用行情”可独立
检查当前代理和 Yahoo 的 NVDA 日线；失败恢复弹窗可直接定位到该设置卡片。

## OpenAI-compatible AI

核心配置为 Base URL、Model 和 API Key；OpenAI、DeepSeek 等兼容 Chat
Completions 的服务共用同一适配器。设置页可从兼容的 `/models` 接口取得模型，
不支持时允许手工填写 Model ID。请求使用：

```text
POST {base_url}/chat/completions
Authorization: Bearer <api-key>
Content-Type: application/json
```

AI 分类输入只包含 symbol、名称、市场、公司描述和 Provider 资产提示。输出必须
能被本地解析为：

```json
{
  "eligible": true,
  "asset_kind": "COMMON_STOCK_OR_ADR",
  "classifications": [
    {"name": "数据中心", "confidence": 0.91}
  ],
  "reason": "简短依据"
}
```

分类最多三个，名称规范化后优先匹配全局已有分类；不存在则自动创建。人工绑定拥有
更高优先级，AI 重跑不得覆盖人工修改。无法确定、schema 无效或服务失败均 fail
closed，不导入可疑资产。

技术解读输入仅含冻结的工具结论和必要指标摘要；输出是纯文本结论。它必须由用户
手动触发，不能修改算法分数、分类或证券资料。

AI 请求同样使用有界恢复：超时和网络错误最多按配置重试 2 次；5xx、429 和返回
格式异常最多重试 1 次；401、403、明确配额不足和其他拒绝不重试。`Retry-After`
支持秒数或 HTTP 日期并封顶 60 秒，等待可被取消。AI 失败只停留在报告弹层，不能
改变确定性运行状态；生成失败时保留旧报告，用户再次点击前不会自动消耗 Token。

## 测试替身

Virtual Provider/AI 与真实适配器实现同一应用端口，覆盖正常、部分失败、基准失败、
认证失败、超时重试、无资料、非目标资产和数据不足。每个 Scenario 可声明
`max_provider_calls`；运行器按证券级外部调用计数并在超出预算时直接失败，以防
重试或熔断回归成请求风暴。普通自动化测试不得访问网络或用户全局配置；真实
smoke 必须显式执行。
